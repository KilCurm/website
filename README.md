# КУБИКУС — лендинг

3D-печать · моделирование · детали.
Одностраничный сайт на чистом HTML/CSS/JS. Без сборки, без npm.

## Структура проекта

```
/
├── index.html              ← единственная страница
├── README.md               ← этот файл
└── assets/
    ├── css/
    │   ├── base.css        ← reset, :root-токены, body, a, img
    │   ├── layout.css      ← .container, .section, .section-title, .red-line
    │   ├── components.css  ← кнопки, header, hero, секции, форма, footer, медиазапросы
    │   └── pages.css       ← переопределения под конкретные страницы (пока пусто)
    ├── js/
    │   ├── nav.js          ← плавный скролл по якорям
    │   └── form.js         ← отправка формы в Formspree (fetch), кнопка-индикатор
    └── img/
        ├── favicon.svg     ← иконка вкладки (логотип «К»)
        ├── logo.svg        ← основной логотип (шапка, подвал)
        ├── icons.svg       ← SVG-спрайт с <symbol> для всех иконок
        ├── og-image.webp   ← OG-картинка для превью (1200×630)
        ├── hero/           ← фон hero и contact (hero.webp)
        └── portfolio/      ← картинки работ (work-1..4.webp — AI-заглушки)
```

CSS подключается в `<head>` в порядке **base → layout → components → pages** — порядок важен, не менять.

JS подключается в конце `<body>` с `defer`, порядок не важен.

Пути к CSS, JS и картинкам — **абсолютные** (`/assets/...`).

## Локальный запуск

Только через локальный сервер — из-за абсолютных путей `file://` не работает.

```bash
python -m http.server 8000
```

Открыть: <http://localhost:8000>

Запускать из корня проекта (там, где `index.html`).

## Деплой

Уже настроен на Netlify / Vercel — при пуше в основную ветку репозитория сайт пересобирается автоматически. Отдельных действий не требуется.

Прод-URL: <https://kubicus.ru/> (прописан в `og:url`). После переключения DNS — проверить, что TLS-сертификат валиден: без него VK/Telegram могут не подтягивать превью.

## Как добавить новую страницу

Например, `about.html`:

1. Скопировать `index.html` → `about.html`.
2. В `<head>` обновить:
   - `<title>`
   - `<meta name="description">`
   - OG-теги (`og:title`, `og:description`, `og:url`)
3. Подключить те же 4 CSS в том же порядке и те же 2 JS с `defer`. Пути уже абсолютные (`/assets/...`), менять не нужно.
4. Удалить секции, которые не нужны, оставить нужные.
5. Если нужны переопределения конкретно под эту страницу — писать их в `pages.css` (не в `components.css`).
6. Ссылку на новую страницу добавить только в `<nav>` шапки (или в burger-меню, когда появится). Footer навигацию не содержит.

## Соглашения

### CSS

- Все цвета, отступы, радиусы, тени, шрифты — **только через `:root`** в `base.css`. В компонентах — `var(--space-4)`, `var(--red)` и т.п., не голые числа.
- Токены отступов: `--space-1..8` = 4, 8, 12, 16, 24, 32, 48, 64 px.
- Токены радиусов: `--radius-sm/md/lg` = 4, 8, 12 px.
- Тени: `--shadow-sm`, `--shadow-md`.
- Именование — BEM-lite: `.service-card__title`, `.btn--outline`. Утилитарные классы (`.mt-20`) не вводим.
- Медиазапросы — в конце того файла, где живёт компонент, не отдельным блоком.
- `header` и `footer` — самодостаточные, завязаны на `.site-header` и `.site-footer`, не зависят от родителя.

### JS

- Каждый файл — IIFE с проверкой на наличие элемента:

  ```js
  (function () {
      var el = document.querySelector('...');
      if (!el) return;
      // ...
  })();
  ```

  Скрипт не падает на странице без этого элемента.

### Картинки

- Все рабочие картинки — **WebP**. JPG/PNG/др. — только как источник, в репозиторий не кладём.
- Пути в CSS — абсолютные: `url("/assets/img/hero/hero.webp")`, не `../img/...`.
- Пути в HTML — абсолютные: `src="/assets/img/portfolio/work-1.webp"`.
- Hero и contact используют **один и тот же** `hero/hero.webp` (в `components.css`, через `background-image`). Разводить на два файла не планируем.
- Портфолио (`work-1..4.webp`) — `<img>` с `width="800" height="800"`, `loading="lazy"`, `decoding="async"`. Кроп 1:1 (`aspect-ratio: 1 / 1` + `object-fit: cover`).
- **AI-фото портфолио — временные заглушки.** При появлении реальных фото деталей — заменить `work-1..4.webp` при сохранении имён и размеров (800×800). Alt'ы при необходимости обновить по смыслу.

### Иконки (SVG)

- Иконки хранятся в едином SVG-спрайте `assets/img/icons.svg` внутри тегов `<symbol>`.
- Подключение в HTML через `<use>`: `<svg><use href="/assets/img/icons.svg#icon-name"></use></svg>`.
- У всех `viewBox="0 0 24 24"`. Размеры (width/height) задаются через CSS для классов-контейнеров (например, `.service-icon svg`), цвет зашит внутри файла `icons.svg` (не наследуется через `currentColor` из-за подключения внешним файлом).
- Все иконки декоративные: контейнеры имеют `aria-hidden="true"`.

### Отчёты по сессиям

- Блоки «было / стало» давать **отдельно друг от друга**, каждый в своём код-блоке — так удобнее копировать по частям.
- Сообщения коммитов давать **готовым текстом** для вставки в `COMMIT_EDITMSG` (редактор `git commit` без `-m`), не в виде `git commit -m "..."`. Так многострочные сообщения копируются без ручной сборки `\n`.
- Если файл сам содержит тройные бэктики (например, `README.md`), оборачивать его в **четыре** бэктика (```` ```` ````). Тройные внутри не закроют внешний блок, и файл скопируется целиком без разрыва форматирования.
